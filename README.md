# سوق السودان

متجر سوداني بالعربية واتجاه RTL مبني بـ Next.js (App Router) وTailwind CSS وDrizzle ORM وPostgreSQL. يشمل صفحات الأقسام والمنتجات والبحث والمفضلة، وسلة للزائر أو العميل، وشراءً دون حساب، ولوحة إدارة محمية على `/admin`.

## الإعداد قبل النشر

1. أنشئ قاعدة PostgreSQL، واحتفظ بنسخة احتياطية إذا كانت القاعدة مستخدمة من نسخة سابقة.
2. انسخ `.env.example` إلى `.env.local` محلياً، أو أضف المتغيرات التالية في **Vercel → Settings → Environment Variables** للبيئات المطلوبة:

| المتغير | الاستخدام |
| --- | --- |
| `DATABASE_URL` | مطلوب لتشغيل المتجر؛ رابط PostgreSQL. استخدم الاتصال المجمّع (pooled) وSSL بحسب مزود القاعدة. |
| `ADMIN_EMAIL` | بريد المدير الوحيد المخوّل. |
| `ADMIN_PASSWORD` | كلمة مرور المدير؛ 8 أحرف على الأقل، و72 بايت UTF-8 كحد أقصى. استخدم كلمة قوية وفريدة. |
| `CLOUDINARY_CLOUD_NAME` | اسم حساب Cloudinary لرفع الصور. |
| `CLOUDINARY_API_KEY` | مفتاح Cloudinary، على الخادم فقط. |
| `CLOUDINARY_API_SECRET` | سر Cloudinary، على الخادم فقط؛ لا تضفه إلى متغير يبدأ بـ `NEXT_PUBLIC_`. |
| `SEED_SAMPLE_DATA` | اختياري: `true` لإضافة مجموعة منتجات وصور توضيحية إلى قاعدة فارغة مرة واحدة؛ الافتراضي `false`. لا تُضاف حسابات أو طلبات أو تقييمات تجريبية. |
| `SUPPORT_EMAIL` | اختياري: بريد التواصل في صفحة المساعدة. |

3. عدّل حسابات البنوك والمحافظ في **`src/lib/payment-accounts.ts`**. الأسماء والأرقام الموجودة افتراضية وليست حسابات حقيقية؛ لا تستقبل تحويلات حقيقية قبل تحديثها.
4. راجع رسوم التوصيل وحد التوصيل المجاني في **`src/lib/constants.ts`**. القيم المبدئية للتجربة هي 2,500 ج.س، والتوصيل المجاني من 50,000 ج.س. تحتاج العمليات الفعلية إلى ترتيب التوصيل في الولايات مع مزود شحن مناسب.
5. أعد النشر بعد إضافة المتغيرات أو تعديل الملفات. في Vercel استخدم أمر البناء `npm run build` وNode.js 22 أو إصداراً مدعوماً من Next.js.

## المدير والأمان

- عند **أول طلب وقت التشغيل** تُنشأ الجداول إن لزم الأمر، ويُنشأ حساب المدير من `ADMIN_EMAIL` و`ADMIN_PASSWORD`، مع تجزئة كلمة المرور بواسطة **bcrypt**. لا توجد بيانات دخول افتراضية في الكود أو واجهة الدخول. إذا لم يُضبط المتغيران بشكل صحيح، لا يُمنح أحد صلاحية الإدارة.
- سجّل الدخول من `/admin` باستخدام متغيرات البيئة. لتدوير كلمة المرور حدّث `ADMIN_PASSWORD` ثم أعد النشر؛ تُلغى جلسات المدير السابقة عند تغييرها. تصبح الحسابات الإدارية القديمة غير المطابقة للبريد المعين غير مخوّلة، وتُعطّل كلمات مرورها وجلساتها عند إعداد المدير الجديد.
- خزّن متغيرات البيئة في مزود الاستضافة، ولا تضعها في Git. مفاتيح Cloudinary تُستخدم على الخادم فقط. الجلسات تحفظ كتجزئة، وطلبات التعديل تتحقق من المصدر، ومحاولات تسجيل الدخول محدودة في PostgreSQL عبر نسخ الخادم المختلفة. يُنصح أيضاً بتفعيل حماية Vercel من الإساءة والنسخ الاحتياطي للقاعدة.
- يمكن للزائر رؤية طلبه وإلغاؤه قبل الشحن من نفس المتصفح عبر ملف تعريف ارتباط آمن لمدة 30 يوماً؛ لا تسمح واجهة الطلبات لأي زائر آخر بقراءة الطلب. العميل المسجّل يتابع طلباته من حسابه.

## رفع الصور

أنشئ حساب Cloudinary (تتوفر خطة مجانية وفق حدود الخدمة) وأضف متغيراته الثلاثة. في إضافة/تعديل المنتج اختر ملفاً من الجهاز؛ الرفع يتم من مسار خادم محمي للمدير، ثم يُحفظ رابط الصورة في PostgreSQL. الصيغ JPG وPNG وWebP فقط، وبحد 4 ميجابايت لكل صورة و6 صور للمنتج. يمكن أيضاً إضافة صورة للقسم. الصور لا تُحذف تلقائياً من Cloudinary عند حذف المنتج، فأدر التخزين من لوحة Cloudinary عند الحاجة.

## الدفع والطلبات

- الدفع عند الاستلام، والتحويل البنكي من قائمة البنوك السودانية، والمحافظ mCash وZain Cash متاحة في صفحة الطلب. اختيار البنك أو المحفظة يُظهر بيانات المتجر من ملف الإعداد المذكور أعلاه.
- **التحويلات والمحافظ يدوية، وليست تكاملاً مع بوابة دفع**: لا يُخصم مبلغ تلقائياً ولا يثبت الدفع تلقائياً. يمكن للعميل إضافة مرجع التحويل، ويراجعه المدير ويغيّر حالة الدفع يدوياً في `/admin/orders`.
- يقرأ الخادم الأسعار والمخزون من قاعدة البيانات ويقفل المنتجات أثناء إنشاء الطلب لمنع بيع آخر قطعة مرتين. الإلغاء يعيد المخزون؛ حذف طلب غير ملغي أو غير مُسلّم يعيده أيضاً. تُحفظ لقطات المنتجات داخل الطلبات القديمة حتى بعد حذف المنتج.

## تشغيل محلي واختبارات

```bash
npm ci
# اضبط متغيرات .env.local كما سبق
npm run dev
# http://localhost:3000

npm run typecheck
npm run lint
npm run build
```

البناء لا يحتاج `DATABASE_URL`؛ الاتصال يُنشأ بتأخير داخل دالة عند استعلام وقت التشغيل، والصفحات والمسارات الديناميكية لا تستعلم أثناء البناء. لكن تشغيل المتجر فعلياً يحتاج قاعدة PostgreSQL صالحة، وحساب Cloudinary لرفع الصور.

للاختبار الشامل، شغّل التطبيق على **قاعدة اختبار معزولة قابلة للمسح** واضبط متغيرات المدير والقاعدة نفسها في الصدفة، ثم نفّذ:

```bash
TEST_ALLOW_MUTATIONS=1 npm run test:integration
# يمكن تعيين TEST_BASE_URL إذا كان الخادم على عنوان آخر
```

ينشئ الاختبار بيانات وطلبات ويحذفها، ويختبر تسجيل المدير، صلاحيات الإدارة، CRUD، تسجيل العميل ودمج سلته، خصوصية الطلبات، الدفع اليدوي، وإغلاق المخزون المتزامن. اختبار Cloudinary الفعلي يتطلب بيانات اعتماد صالحة واتصالاً بالخدمة؛ الاختبار الآلي يغطي الحماية ورفض الملف غير الصالح أو عدم الإعداد.

## ترقية متجر قائم

التهيئة الذاتية تستخدم قفل PostgreSQL لتسلسل طلبات التشغيل الأولى. إذا كانت جداول النسخة السابقة موجودة، تُضيف حقول الولاية والدفع ووصول الزائر دون حذف المنتجات أو العملاء أو الطلبات. يجب أن يملك مستخدم القاعدة صلاحيات إنشاء/تعديل الجداول، ويُنصح بتجربة الترقية أولاً على نسخة احتياطية. يُحتفظ بكلمات مرور العملاء القديمة بصيغة scrypt عند الدخول للتوافق، بينما تُستخدم bcrypt لكلمات المرور الجديدة وللمدير.

**لم تُحوَّل الأرقام المالية القديمة تلقائياً من عملة أخرى.** المبالغ المخزنة تُمثّل الآن أجزاء الجنيه السوداني (100 جزء لكل ج.س)، لذا راجع أسعار المنتجات ورسوم الشحن والطلبات القديمة قبل استقبال الطلبات الحقيقية. البيانات النموذجية القديمة، إن كانت موجودة في قاعدتك، لن تُحذف تلقائياً.
